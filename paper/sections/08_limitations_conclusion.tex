\section{Limitations}
\label{sec:limitations}

\paragraph{Evidence.}
Each cell is one greedy run; intervals capture question sampling only. One LLM judge grades everything, validated against a larger judge, not humans. KU-past cells have \nm{datasets/heldout138/KU_past} questions and the regression and MemConflict strata are small; overlapping intervals are reported as no effect.

\paragraph{Models and data.}
The cloud readers, extractor and judge are served through an API and can change; the cache makes our runs replayable, not re-executable against the same weights. The dev split used to calibrate $\tau$ and $\theta$ was extracted with the local gemma4 extractor, the evaluated sets with glm-5.3-flash. MemConflict is synthetic: \nm{memconflict_audit90_r2/both_clean} of \nm{memconflict_audit90/n} evaluated questions are clean for both of our raters, below the gate we set, and static conflicts are the weakest type (Appendix~\ref{app:memconflict}); the audit used two LLM raters ($\kappa=\nm{memconflict_audit90_r2/kappa_binary}$) and has not been reviewed by a human. The replayed Shadow sweep differs from the original run in one temporal-reasoning cell at two thresholds; KU columns are unchanged.

\paragraph{Extraction, latency and scope.}
Every fact-based system is capped by its extractor: truncated assistant turns and inconsistent key reuse (missed merges) cost answers that the WAL tail recovers only while a session is in flight. Latency comes from one machine, ten dev questions and one lag. Epoch precedence assumes that newer means more correct, which fails for false corrections, and the 12B reader loses temporal accuracy when the WAL tail is in the prompt, for reasons we did not isolate.

\section{Broader Impact}
\label{sec:impact}

Keeping every version of a user's facts also retains values the user corrected or wants gone, so versioned memory needs user-visible deletion of all versions and retention limits. The raw WAL holds conversation text until extraction commits and needs the same access control as the fact store; ours trims it on commit. A later false statement can exploit the precedence rule, so one newer statement should not silently override a stable fact. We use public benchmark and synthetic dialogues only.

\section{Conclusion}
\label{sec:conclusion}

Moving fact extraction off the write path makes a memory system fast to acknowledge and stale to read. A write-through log of raw turns with monotonic epochs, read with the committed facts in epoch order, closes most of that gap; keeping every version preserves the answers about earlier values that write-side and read-side ``newest value only'' rules erase, as \memzero{} OSS also shows. Newer is not always correct, though: false corrections need a trust policy that chooses among the stored versions.
