\section{Limitations}
\label{sec:limitations}

\paragraph{Evidence.}
Each cell is one greedy run; intervals capture question sampling only. The stream ends right after the update, so the staleness rates are conditional on the update being in flight, a worst case rather than a deployment rate. qwen3.8-flash grades everything; judge validation spans three model families (a larger qwen judge, claude-haiku-5-5 on every answer, and a GPT-family model on a \nm{tab12/codex50/n}-row check sheet), and the human check is a single-author blind audit of that sheet: stale reads rest on only \nm{human_audit/stale_read/n} KU rows, and its \nm{human_audit/failing_abstention_rows} failing abstention rows cover only \nm{human_audit/failing_abstention_distinct} distinct questions. KU-past cells have \nm{datasets/heldout138/KU_past} questions and the regression and MemConflict strata are small; non-significant paired differences are reported as no effect.

\paragraph{Models and data.}
The cloud readers, extractor and judge are served through an API and can change; the cache makes our runs replayable, not re-executable against the same weights. The dev split used to calibrate $\tau$ and $\theta$ was extracted with the local gemma4 extractor, the evaluated sets with glm-5.3-flash. MemConflict is synthetic: \nm{memconflict_audit90_r2/both_clean} of \nm{memconflict_audit90/n} evaluated questions are clean for our first two raters and \nm{tab8/all/evaluated/clean_all4} for all four, below the gate we set, and static conflicts are the weakest type (Appendix~\ref{app:memconflict}); the raters are LLMs from three families (Fleiss' $\kappa=\nm{tab8/kappa_fleiss4}$) and no human has reviewed the audit. The replayed Shadow sweep differs from the original run in one temporal-reasoning cell at two thresholds; KU columns are unchanged.

\paragraph{Extraction, latency and scope.}
Every fact-based system is capped by its extractor: truncated assistant turns and inconsistent key reuse (missed merges) cost answers that the WAL tail recovers only while a session is in flight. Latency comes from one machine, ten dev questions and one lag, and the cost of a durable log was measured on a loaded machine. Newer-wins ordering assumes that newer means more correct, which fails for false corrections. The 12B reader loses temporal accuracy when the WAL tail is in the prompt; our probes rule out prompt length and point to how raw turns are dated and placed, but no single change closes the gap.

\section{Broader Impact}
\label{sec:impact}

Keeping every version of a user's facts also retains values the user corrected or wants gone, so versioned memory needs user-visible deletion of all versions and retention limits. The raw WAL holds conversation text until extraction commits and needs the same access control as the fact store; ours trims it on commit. A later false statement can exploit newer-wins ordering, so one newer statement should not silently override a stable fact. We use public benchmark and synthetic dialogues only.

\section{Conclusion}
\label{sec:conclusion}

Moving fact extraction off the write path makes a memory system fast to acknowledge and stale to read. A write-through log of raw turns with monotonic epochs, read with the committed facts in epoch order, closes most of that gap; keeping every version preserves the answers about earlier values that write-side and read-side ``newest value only'' rules erase, as \memzero{} OSS also shows. Newer is not always correct, though: false corrections need a trust policy that chooses among the stored versions.
